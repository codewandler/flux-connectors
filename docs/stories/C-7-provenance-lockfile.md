# Record provenance and write connectors.lock

## Goal
Make drift detectable: every generated artifact records the hashes and versions of everything that
produced it, so upstream movement and stale output are caught rather than silently absorbed.

## Acceptance
- [x] `Provenance` captures source URL, upstream version, fetched-at, and sha256 of the vendor spec
      and the provider TOML. **Not the IR hash** — it is computed *from* the serialized IR, so
      storing it inside the value being hashed has no fixed point. It belongs in `connectors.lock`.
- [x] **The hash domain excludes `fetched_at`.** C-2's review found that `canonical_json()` currently
      includes it, so two fetches of byte-identical spec bytes would produce different IR hashes —
      exactly the phantom drift this story exists to prevent. Define and test the hash domain
      explicitly rather than hashing the whole Connector.
- [x] `connectors.lock` serializes one entry per provider, including the generator version, in a
      stable, diff-friendly order.
- [x] Recomputing hashes over unchanged inputs reproduces the lockfile byte-for-byte — the test that
      makes `check` (`C-14`) trustworthy.
- [x] Changing any input (spec, TOML, or generator version) changes the corresponding hash and only
      that hash.

## Progress
- **Implemented** in `crates/connector-spec/src/lock.rs` (the `connectors.lock` model) and
  `Connector::hash_domain` / `Connector::ir_sha256` in `src/ir.rs`. Pinned by
  `tests/lockfile.rs` (16 tests).
- **The hash domain, stated exactly.** *In:* `id`, `vendor`, `base_url`, `description`, `auth`,
  `default_auth`, `operations` — the connector's compiled meaning. *Out:* **all of `Provenance`**,
  not only `fetched_at`. `fetched_at` is the field the review caught, but the rule generalizes:
  provenance says where the bytes came from, and every one of its fields is already recorded and
  verified as its own lockfile column, so hashing it here would double-count it and would move
  `ir_sha256` for edits that change no generated byte. The sharp case is pinned by
  `a_comment_only_edit_moves_the_toml_hash_alone`. `canonical_json()` is unchanged and still encodes
  provenance — the domain is a projection, not a deletion.
- The domain is a real type (`ir::HashDomain`) built by exhaustively destructuring `Connector`, so a
  field added later fails to compile until someone states which side of the line it is on. Silently
  inheriting that decision is how `fetched_at` got in.
- **No timestamp reaches the lockfile at all**, which is what makes "unchanged inputs reproduce it
  byte for byte" true across a re-fetch rather than only within one build.
- `LockEntry::upstream_spec_sha256` is present and optional, so **C-25**'s second babelforce hash is
  one field rather than a reshape of every row (`a_second_spec_hash_is_additive`).
- **For C-13/C-14**, the public API is `Lockfile::{new, insert, entry, entries, version, to_toml,
  parse}`, `LockEntry::{for_connector, with_artifact, with_upstream_spec_sha256}`, `sha256_hex`,
  `LOCKFILE_NAME`, `LOCKFILE_VERSION`. Artifact hashes are supplied by the caller — this crate does
  not emit artifacts and still performs no IO.

## Notes
- Depends on `C-2`'s deterministic IR serialization; nondeterminism there shows up here as phantom
  drift on every build.
- The lockfile holds hashes and versions only — never a credential, never a resolved endpoint URL.
